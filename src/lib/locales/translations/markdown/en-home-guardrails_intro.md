Everyone uses AI. Not everyone uses it well. Even fewer know how to align a
team on it. I build that alignment.

At The New Business, that meant eight live client sites: three new builds I
shipped in three months, five inherited ones kept stable through the same
guardrails. The design vision held because the alignment did.

My approach is a system: conventions, workflows, custom linting rules,
commit gates, tests, CI. All version-controlled, all loaded at the start of
every session, the same for me and for anyone joining the project. Some
pieces travel with me across projects; others live in the repo and stay
with the team. Either way, anyone joining, human or AI, picks up the same
conventions on day one.

Each project picks what it needs from the toolkit: rules for conventions
(where things live, naming patterns, Tailwind versus CSS Modules), skills
for workflows, CLI bindings when the assistant needs to check itself,
custom pipelines when a single prompt isn't enough. I start light and
converge as the project evolves. The cards below break the system down.
