Interface systems should let you change direction without rebuilding everything.

I specialize in interface infrastructure: component APIs, theming systems, and
design tokens that keep mockups and code aligned. This reduces long-term technical debt
caused by frameworks chosen for early velocity over project fit.

I start with lightweight constraints to establish a clear baseline. When the
work proves more structure is needed, I add it deliberately. I build composable
primitives with accessible, responsive defaults. As complexity grows, the UI
stays aligned with design intent.

Whatever the project, I work end-to-end with designers, product, and
engineering, explaining trade-offs in plain language and making accessibility a
default rather than an add-on. I look beyond the immediate feature to the
business goal it serves and to the internal processes around it, refining how we
ship as much as what we ship. Done well, the system honours the design intent
without slowing the team down.
