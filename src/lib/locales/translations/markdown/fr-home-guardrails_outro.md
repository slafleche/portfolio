Construire des systèmes évolutifs, c’est aligner trois cibles : la vision de
design, l’utilisateur final, et les développeurs qui maintiennent le code.

La troisième est facile à oublier, mais c’est elle qui détermine si la vision
survit.

Quand une base de code est frustrante à travailler, la qualité s’érode. Pas
parce que les équipes ne se soucient pas, mais parce que le système rend ce
soin coûteux. Les développeurs prennent des raccourcis, évitent les
refactorings, laissent tomber le polissage. Les petites incohérences
s’accumulent.

Quand le code est lisible, prévisible et facile à modifier, les équipes
investissent. Elles refactorisent, elles ajoutent des tests, elles règlent les
cas limites. Une bonne infrastructure rend la bonne chose plus facile à faire
que la mauvaise.

De bons garde-fous fonctionnent peu importe qui écrit le code, humain ou IA.
L’IA a juste rendu le problème universel.
